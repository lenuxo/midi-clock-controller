# Ableton Link 同步

简体中文 · [English](ableton-link.en.md)

应用同时作为 Link 参与者和 USB MIDI 时钟桥。主控 Link 关闭时沿用本地时钟；开启后，所有跟随 MIDI 设备从 Link 共享拍点生成 24 PPQN Clock。独立设备保留自己的速度、启停与本地时间线。

设备卡片上的 **MIDI Clock** 表示实际输出协议；「拍点来源：Link」表示 Link → MIDI 桥接，「本地主控」或「独立时钟」表示本地时钟。「Link 会话」独立汇总其他参与者数量、共享速度与拍点、本机启停联动状态；「MIDI 设备」逐台展示本机输出。Link 不提供参与者名称及逐台连接、同步或播放状态，不生成可逐台操控的 Link 卡片。断线卡片上的标签表示同步配置，不代表设备当前正在接收时钟。

## 使用

1. 停止主控后，点击主控卡片的 **Link**。独立设备无需停止。Link 每次启动应用时默认关闭，不自动联网或自动播放。
2. 在同一电脑上的另一款应用，或同一局域网内的另一台设备上开启 Link。会话卡片数量表示其他 Link 参与者，不是 USB 设备数量；没有其他参与者时保持当前节奏。
3. 加入已有会话会采用会话速度，不把本地保存的 BPM 强加给会话。双方都能改速；主控加减号、输入框和键盘上下键修改的是共享速度。
4. 在卡片内的「MIDI 开始对齐」选择「下一拍」或「每 4 拍」作为开始边界，与启停联动独立。此设置需停止主控后修改。「每 4 拍」是启动边界，不代表所有参与者采用相同拍号。
5. 开始或继续时显示等待状态，主按钮变为「取消开始」；取消不会补发旧消息。从头开始发送 Start，继续发送 Continue 并保留硬件自己的位置，不能保证乐曲位置一致；停止不等待拍点。
6. 「启停控制」默认选择「本机」，只控制本机 MIDI 播放，不发送或跟随远端启停；切换到「联动」后，与其他也开启该功能的参与者交换新的启停意图。开启设置或加入会话不会执行历史播放命令。远端开始会继续符合条件的设备，其余设备从头开始，独立设备不参与。
7. 主控停止会广播停止（启停联动开启时）。顶部「全部停止」只停止本机 MIDI，取消待开始任务并关闭启停联动，避免后续远端播放使硬件重新启动。Link 速度与拍点连接仍保留。
8. 点击「退出」离开 Link 会话，保留当前速度；最后一个参与者离开不会自动停止。硬件断线重连不自动播放，仍遵守 30 秒移除规则。

## 范围和异常

- Link 原始速度超出 20–300 BPM 时，MIDI 使用二倍或半倍的整数次幂比例落入范围；界面显示原始 Link BPM 及具体比例（例如「Link 999.0 BPM · MIDI ÷4」对应 249.75 BPM，数位屏按一位小数显示 249.8），不静默截断。编辑折算后的 MIDI BPM 时优先按同一比例发布；跨出该比例适用区间的显式编辑恢复 1:1，以保证实际输出采用输入的速度。
- 同一台硬件应选择一条同步路径，避免同时接收 Link 与 MIDI，或多个桥接器输出的时钟。
- Link 拍点突然跳变或调度严重迟到时，停止受影响设备并显示错误，不补发过期脉冲。USB、硬件处理及音频输出延迟仍需实际测量；不宣称软件同步等于声音已对齐。
- 无参与者不必然代表没有同网设备：检查双方 Link 开关、网络隔离、防火墙及 macOS 本地网络权限。首次联网可能出现系统权限提示。

## 实现与依赖

- 官方 Ableton Link 4.1.1，固定提交及 Asio 子模块版本见 `Sources/CLink/vendor/README.md`。使用官方 `Link.hpp`，薄 C ABI 负责快照和命令，不包含 Link Audio。
- `LinkBridge` 在 macOS host time 上获取会话快照；`BeatTimeline` 保留实际时间/拍点映射，调度不使用界面显示 BPM 的近似值。每个 MIDI 引擎在专用串行队列获取快照并发送未来时间戳，UI 的 50 ms 轮询只更新显示和观察启停，不驱动 MIDI 脉冲。
- 量化启动的 Start / Continue 仅在进入 8 ms 输出窗口时提交，比首个 Clock 早 1 ms；等待期间取消不向端点提交 transport。已发送消息仍按本引擎的顺序排空，不清空 destination。
- 当前接入增加第三方运行时代码依赖，必要性是复用官方网络发现、会话协作和时钟漂移补偿。构建使用随源码固定的头文件，不在构建时联网下载。
- Link 的 GPLv2+ / 专有许可说明和 Asio 的 Boost Software License 随源码及本地 app 打包；关于窗口的「查看第三方授权」打开授权目录，同时包含 DSEG 字体授权。主项目采用 GPL-2.0-or-later，并随 Release 提供完整对应源码与构建脚本；见根目录 LICENSE 和 COPYING.md。

## 验证

普通测试：

```sh
CLANG_MODULE_CACHE_PATH="$PWD/.build/clang-cache" swift test --disable-sandbox
```

强制运行私有 CoreMIDI 集成及真实双 Link 参与者网络测试：

```sh
REQUIRE_MIDI_TESTS=1 REQUIRE_LINK_NETWORK_TESTS=1 CLANG_MODULE_CACHE_PATH="$PWD/.build/clang-cache" swift test --disable-sandbox
```

网络测试会短暂创建两个真实 Link 参与者，只在隔离测试网络运行；若发现其他参与者则拒绝改速/启停并报告跳过。MIDI 测试只向私有虚拟端口发送消息，不连接物理设备。Debug 预览的 Link 与 MIDI 均为模拟实现，不联网、不发送 MIDI。

真实设备验收：用 Live 或其他 Link 应用与本应用双向改速；开启双方启停联动，测试等待取消、快速启停和 Continue；让独立 MIDI 设备保持不同速度，确认不受影响。录制硬件节拍音与 Link 参考节拍，检查静态偏移及长期漂移。最后测试网络中断、参与者退出、硬件断线重连与全部停止。

### 启停事件识别

使用官方 `setStartStopCallback` 记录线程安全的启停变化序号；捕获状态时保持序号一致，UI 观察变化而非将 `timeForIsPlaying` 当成命令 ID。后者可能随速度及时间线校准重映射，不能据此重启设备。发送本机命令前记录意图，下一次观察核对最终状态，避免并发远端反向操作被当作本机确认吞掉；本机异步回调不重复触发播放。加入或开启联动仍不自动执行会话中的历史播放命令。

回归覆盖并发反向操作、时间线校准、延迟本机确认、无 MIDI 输出及快速交替启停。真实双端网络测试会先检查是否存在其他参与者，存在时跳过且不发送命令；不能将此跳过视为网络互通验证通过。

### Ableton Move 复测

按 [Move 官方说明](https://www.ableton.com/en/move/manual/#using-ableton-link-on-move)，在 Move 的 Setup → Link 选择 **Start/Stop**；**Tempo** 只共享速度。应用加入会话并选择「启停控制 → 联动」，确认其他参与者数量非零。先让两端停止，再用 Move 的 Play 开始、停止各 5 次，检查应用主控及跟随 MIDI 卡片的状态；然后反向操作。将 MIDI 开始对齐设为「下一拍」以减少观察等待，最后再测试「每 4 拍」的等待与取消。只检查 Link 联动时可不接 MIDI 输出。此步骤是待执行的硬件验收，不代表已验证 Move。
